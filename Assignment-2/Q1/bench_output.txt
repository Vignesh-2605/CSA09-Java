Q1  -  BUILDING TEXT UNDER LOAD: String vs StringBuilder vs StringBuffer
======================================================================================================================
Name: Vignesh S   Register Number: 192325002
Harness: 5 warm-up runs discarded, 11 measured repetitions, MEDIAN reported.

1.  PREDICTION  (recorded before any measurement was taken)
----------------------------------------------------------------------------------------------------------------------
  A String is immutable, so s = s + f cannot extend the existing object.
  It must allocate a new character array, copy everything already written
  into it, then append the new field.  Building a ticket of n fields
  therefore copies 1 + 2 + 3 + ... + n field-widths of text, which is the
  arithmetic series n(n+1)/2 - that is O(n^2) CHARACTERS COPIED for O(n)
  characters of output, and it allocates two throwaway objects per field.

  StringBuilder keeps ONE growable char array and writes each character
  once, so it is O(n) characters copied and allocates a constant number of
  objects regardless of n.  StringBuffer does exactly the same work with
  every method synchronized.

  ID     | PREDICTED OUTCOME                  | REASONING
  ------------------------------------------------------------------------------------------------------------------
  W1     | all five within noise of another   | 12 fields is too few for n^2 to matter
  W2     | concat clearly slowest, but finite | 50 fields each; n^2 is small, repeated 10,000x
  W3     | concat catastrophically slowest    | 4,000 fields in ONE ticket: n^2 dominates
  all    | StringBuffer a little behind SB    | same algorithm, plus uncontended lock overhead
  all    | pre-sized SB fastest of the three  | no internal array doubling at all

  Quantified prediction for W3: the + loop copies roughly 4,000/2 = 2,000
  times as many characters as StringBuilder, so if the characters copied
  dominate, the gap should be of that order - hundreds to thousands of
  times, NOT a few percent.
