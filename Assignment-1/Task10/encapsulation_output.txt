TASK 10  -  PACKAGES, ACCESS MODIFIERS AND ENCAPSULATION
================================================================================

1.  PACKAGE STRUCTURE AND THE DIRECTION OF DEPENDENCY
--------------------------------------------------------------------------------
  parking.model    Vehicle, TwoWheeler, Car, ElectricCar, Chargeable,
                   Slot, SlotFactory, ParkingTicket
                   -> WHAT the system is.  Depends on nothing.
  parking.service  Facility, SlotGrid (package-private),
                   SlotRow (package-private)
                   -> HOW the operations work.  Depends on model only.
  parking.app      EncapsulationDemo, AutoboxingRiskDemo
                   -> the gate console.  Depends on model + service.

      parking.app  ---->  parking.service  ---->  parking.model

  The arrows point one way only.  parking.model never imports service
  or app, so the whole domain compiles and can be tested with no
  facility and no user interface present at all.

2.  ACCESS MODIFIER CHOSEN FOR EACH MEMBER, AND WHY
--------------------------------------------------------------------------------
MEMBER                       | MODIFIER     | REASON
--------------------------------------------------------------------------------
Vehicle.regNo                | private      | identity; no code anywhere may change it
Vehicle(String,int)          | protected    | only subclasses build vehicles
Vehicle.ratePerHour()        | protected    | a raw rate is a model-internal detail
Vehicle.dailyCap()           | protected    | specialisable by subclasses only
Vehicle.calculateFee()       | public final | service must bill; rule must not vary
Vehicle.getRegNo()           | public       | everyone may read identity
Slot.occupy() / free()       | default      | only parking.model may change occupancy
Slot.Slot(int,int)           | default      | slots are created through SlotFactory
SlotGrid, SlotRow            | default      | storage layout is a service-internal detail
Facility.grid                | private      | the layout cannot be reached or replaced
ParkingTicket fields         | private      | a ticket is read-only once issued
setExitMinute(int)           | public       | the one mutator, and it validates

4.  VALIDATION DONE BY THE GETTERS AND SETTERS
--------------------------------------------------------------------------------
ATTEMPT                                        | OUTCOME
--------------------------------------------------------------------------------
new Car("")                    blank plate     | REJECTED: IllegalArgumentException - registration number is mandatory
new Car(null)                  null plate      | REJECTED: IllegalArgumentException - registration number is mandatory
new ElectricCar("TN9", 0)      zero battery    | REJECTED: IllegalArgumentException - battery capacity must be positive
t1.setExitMinute(400)          before entry    | REJECTED: IllegalArgumentException - exit (400) cannot precede entry (540)
t1.setExitMinute(2000)         not a time      | REJECTED: IllegalArgumentException - exit minute must be 0..1439, was 2000
ev.chargingFee(-5)             negative units  | REJECTED: IllegalArgumentException - units drawn cannot be negative
bike.calculateFee(-30)         negative stay   | REJECTED: IllegalArgumentException - duration cannot be negative
f.admit(bike, 600)             already inside  | REJECTED: IllegalStateException - TN01AB1111 is already inside on ticket 1001
new Facility(new int[]{0})     empty floor     | REJECTED: IllegalArgumentException - every floor needs at least one slot
new Facility(new int[]{})      no floors       | REJECTED: IllegalArgumentException - a facility needs at least one floor

  Each guard lives in exactly ONE place - the setter or the constructor
  of the class that owns the field - so no caller can skip it and no
  caller has to remember it.  That is the practical payoff of private
  fields: the check cannot be bypassed because the field cannot be
  reached.

6.  WHAT THIS PACKAGE CANNOT DO
--------------------------------------------------------------------------------
  Each line below is a COMPILE ERROR, captured for real in
  compile_errors/compiler_errors.txt:
     t1.getSlot().free();          - free() is package-private to model
     new Slot(0, 0);               - the constructor is package-private
     car.ratePerHour();            - protected, not visible here
     new SlotGrid(new int[]{2});   - the class is not public

  Those four errors ARE the encapsulation.  An application that cannot
  free a slot behind the facility's back, cannot invent a slot, cannot
  read a raw tariff and cannot see the storage layout can only drive the
  system through operations that keep its invariants - which is why the
  slot array and the fee rule can both be replaced in Task 12 without
  touching a single line of this file.
