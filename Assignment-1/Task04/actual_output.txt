TASK 4  -  CLASSES, OBJECTS AND CONSTRUCTORS
==============================================================================

1.  THE FOUR CONSTRUCTORS, AND WHICH ONE IS USED WHEN
------------------------------------------------------------------------------
  a) full parameterised  - every fact known at the gate:
      [full constructor ran for TN01AB1111]
     Ticket#1001 TN01AB1111 at 0/0 entry=540

  b) overloaded 3-arg    - slot known, entry time defaults to 09:00:
      [full constructor ran for TN02CD2222]
      [3-arg constructor chained to the full one]
     Ticket#1002 TN02CD2222 at 1/7 entry=540

  c) overloaded 1-arg    - walk-in, slot assigned later:
      [full constructor ran for TN03EF3333]
      [1-arg constructor chained to the full one]
     Ticket#1003 TN03EF3333 at 0/0 entry=540

  d) copy constructor    - driver lost the printed ticket:
      [copy constructor ran: 1001 re-issued as 1004]
     original  Ticket#1001 TN01AB1111 at 0/0 entry=540
     re-issued Ticket#1004 TN01AB1111 at 0/0 entry=540 (DUPLICATE)

2.  WHY A COPY CONSTRUCTOR IS NEEDED HERE
------------------------------------------------------------------------------
  A duplicate must carry the SAME stay (vehicle, slot, entry time) so
  that the fee is unchanged, but a DIFFERENT ticket number, so that the
  rule 'a ticket number is never reused' still holds and the original
  cannot be presented a second time.
  same vehicle?  true     same entry?  true     same number?  false
  marked as a duplicate: true

  A plain assignment would NOT do this:
     ParkingTicket alias = t1;
     alias == t1 ?  true   -> one object with two names, not a copy

3.  CONSTRUCTOR CHAINING WITH this(...)
------------------------------------------------------------------------------
  The 1-arg and 3-arg constructors do no validation of their own; each
  delegates with this(...) to the full constructor, which is the ONE
  place the three guard clauses live.  The trace above shows the full
  constructor running FIRST in every case, because this(...) must be
  the first statement in a constructor body.

  Proof that the shared validation still protects the short forms:
     blank vehicle number     -> REJECTED: vehicle number is mandatory
     negative floor           -> REJECTED: floor and slot cannot be negative

4.  REFERENCE VARIABLES, THE STACK AND THE HEAP
------------------------------------------------------------------------------
  t1, t2, t3, t4 and alias are reference VARIABLES; they live in the
  stack frame of main().  The ParkingTicket OBJECTS they name live on
  the heap.  alias and t1 hold the same address, so there are 4 objects
  on the heap but 5 references on the stack.

     stack (main)              heap
     t1    ----------------->  [Ticket#1001 TN01AB1111]  <--- alias
     t2    ----------------->  [Ticket#1002 TN02CD2222]
     t3    ----------------->  [Ticket#1003 TN03EF3333]
     t4    ----------------->  [Ticket#1004 TN01AB1111 DUP]
     alias ---- same address as t1

  static lastTicketNo is NOT in either place - it belongs to the class
  and lives in the method area, one copy however many tickets exist.
  Tickets issued so far: 4

5.  HOW OBJECTS ARE PASSED TO AND RETURNED FROM METHODS
------------------------------------------------------------------------------
  before closeIt(t2)   : Ticket#1002 TN02CD2222 at 1/7 entry=540
  after  closeIt(t2)   : exit time was set through the reference
  before repoint(t2)   : ticket no = 1002
      [full constructor ran for TN99ZZ9999]
      [1-arg constructor chained to the full one]
  after  repoint(t2)   : ticket no = 1002   (unchanged)

  Java passes the VALUE of the reference.  closeIt() could change the
  object because it followed the same address; repoint() only rebound
  its own local copy of the reference, so main()'s t2 still names the
  original object.  This is why a method cannot swap two objects for
  its caller, and why the facility returns a NEW ParkingTicket rather
  than filling in one the caller passed down.
