TASK 5  -  STATIC MEMBERS AND THE OBJECT LIFE CYCLE
================================================================================

1.  THE STATIC BLOCK RUNS BEFORE THE FIRST OBJECT EXISTS
--------------------------------------------------------------------------------
  touching a static member forces the class to load:
      [static block: loading the rate table once]
  Ticket.nextTicketNo() = 1001, facility = SIMATS-MLCP
  ...and the rate table is already populated: car rate = Rs 30/hour, with no Ticket object created yet.

  A static block is the right place for this because the rate table is
  the same for every ticket and must exist before any ticket is issued.
  Putting it in a constructor would rebuild the same table for every
  vehicle that entered the campus.

2.  WHY THE TICKET COUNTER MUST BE static
--------------------------------------------------------------------------------
  three tickets issued: Ticket#1001 TN01AB1111, Ticket#1002 TN02CD2222, Ticket#1003 TN03EF3333
  the numbers are distinct and strictly increasing, because the counter
  belongs to the class, not to any one ticket.

  Had lastTicketNo been an INSTANCE variable, every object would start
  its own count from 1000 and all three tickets would be #1001 - which
  breaks the business rule 'a ticket number is never reused' on the very
  second vehicle.  CounterScopeComparison.java in this folder shows that
  failure actually happening.

3.  WHAT ELSE BELONGS TO THE CLASS, AND WHAT DOES NOT
--------------------------------------------------------------------------------
MEMBER               | SCOPE      | WHY
--------------------------------------------------------------------------------
lastTicketNo         | static     | one sequence for the whole facility
liveCount            | static     | occupancy is a property of the facility
totalEverIssued      | static     | a lifetime total cannot live in one ticket
RATE_BY_TYPE         | static     | identical for every ticket; loaded once
FACILITY_CODE        | static     | a constant of the facility
ticketNo             | instance   | each ticket has its OWN number
vehicleNo            | instance   | identifies this one vehicle
entryMinute          | instance   | this stay began at its own time
closed               | instance   | this ticket's own state

4.  LIVE OCCUPANCY TRACKED ON THE CLASS
--------------------------------------------------------------------------------
  issued = 3, inside = 3
  Ticket#1002 TN02CD2222 leaves at 700 -> fee Rs 90
  issued = 3, inside = 2   (issued never falls; inside does)
  closing it twice -> REJECTED: ticket 1002 is already closed

5.  THE OBJECT LIFE CYCLE: WHEN A TICKET BECOMES GARBAGE
--------------------------------------------------------------------------------
  A ParkingTicket is created at entry, closed at exit, and then has no
  further purpose.  It becomes ELIGIBLE for collection at the moment the
  last reference to it disappears - which is when the facility removes it
  from its active-ticket list, NOT when close() is called.

  stage 1  vehicle inside, held by activeTickets and by 'parked'
           weak reference still resolves: true
  stage 2  close() called; the object is STILL reachable from the list
           weak reference still resolves: true
  stage 3  removed from activeTickets and the variable set to null
           after requesting a collection, weak reference resolves: false
           -> the object was reclaimed; the ticket NUMBER is not reused,
              because that lives in the static counter, which survives.
           next ticket would be #1005

6.  HOW OBJECTS ARE PASSED AND RETURNED IN THIS DESIGN
--------------------------------------------------------------------------------
  issue()   RETURNS a new Ticket reference; the caller never supplies one
            to be filled in, so a ticket cannot exist half-built.
  close()   is called ON the ticket and returns a long fee, not an object,
            so the money leaves the ticket as a value and cannot be
            altered afterwards through a shared reference.
  Java passes the VALUE of a reference, so a method that receives a
  Ticket can change that ticket but cannot replace the caller's variable.

  final tally:  issued = 4, still inside = 2
