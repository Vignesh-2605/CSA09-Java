5.  WHAT THIS MEANS FOR THE DESIGN
----------------------------------------------------------------------------------------------------------------
  The table shows TWO independent decisions, and both have to be right.

  Running the load on the EDT freezes the window for the whole fetch -
  the window cannot repaint, cannot be dragged and cannot be closed.
  Moving the SAME load into a SwingWorker fixes the freeze without
  making the load any faster: the user can still see and move the window
  while it runs.

  Pagination then fixes the load itself.  The user is shown 25 rows, so
  fetching 100,000 to display 25 is wasted work no matter which thread
  does it, and the wasted memory is held for as long as the screen is
  open.  This is why EventRegistrationApp uses LIMIT/OFFSET for the
  table and still fetches in a SwingWorker - and why the CSV export,
  which genuinely does need every row, walks the data a page at a time
  instead of holding the whole result set.
